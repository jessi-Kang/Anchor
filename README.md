# Anchor

**내가 오늘 실제로 만난 자료와, 오늘 못 한 말에서 시작하는 언어 학습 작업실.**

가르치지 않는다. 내가 이미 아는 것에서 출발해 내가 직접 추측하게 하고, 마지막엔 반드시 소리 내어 말하게 한다.

> 이 문서가 기준이다. 여기 적힌 것이 만들어지는 중인지로 진행을 본다.
> 설계 세부는 [`docs/SPEC.md`](./docs/SPEC.md), 화면 순서는 [`docs/FLOW.md`](./docs/FLOW.md)에 있지만,
> **그 문서들과 이 문서가 어긋나면 이 문서가 맞다.**

---

## 무엇을 만드는가

한국어를 쓰는 직장인 한 사람이 영어·일본어를 **일하면서** 늘리려고 한다. 학원 갈 시간은 없고, 앱을 켜서 남의 커리큘럼을 따라갈 마음도 없다.

그 사람의 하루에는 이미 재료가 넘친다. 아침에 읽은 영어 기사, 어제 받은 일본어 메일, 회의에서 하려다 못 한 한마디. **Anchor는 그 재료를 받아서, 그 사람이 모르는 것만 골라, 발견하게 만들고, 입으로 꺼내게 하는 작업실이다.**

## 왜 지금 방법으로는 안 되는가

**문제 1 — 모든 앱이 자기 재료로 시작한다.** 앱이 고른 단어, 앱이 정한 순서. 정작 내일 아침 회의에서 읽어야 할 그 문서는 다루지 않는다. 그래서 앱에서 배운 것과 실제로 필요한 것이 만나지 않는다.

**문제 2 — 내가 아는 것을 아무도 안 쓴다.** 한국어를 쓰는 사람은 **한자음을 이미 수천 개 갖고 있다.** "협력"의 "협"을 안다. 그런데 일본어 앱들은 전부 나를 백지로 놓고 `協 = キョウ = cooperation`을 외우라고 한다. 이미 가진 것을 버리고 처음부터 시작하게 만든다.

**문제 3 — 물어봐서 알아내려고 한다.** "초급·중급·고급 중 어디세요?" 이 질문에 정확히 답할 수 있는 사람은 없다. 나는 "협력"은 알고 "協"은 모른다. 그 상태를 표현할 칸이 어디에도 없다.

**문제 4 — 읽기만 하고 끝난다.** 뜻을 알아도 입에서 안 나온다. 발음이 왜 다른지 설명을 들어도 소리가 안 바뀐다.

## 어떻게 다른가 — 장치 셋

### 1. 아는 소리에 닻을 내린다

이름 그대로다. **Anchor = 닻.** 아는 것에 닻을 내리고 새 것을 끌어온다.

- **일본어 한자 ← 한국어 한자음.** "협력의 **협**, 그 글자는 어떻게 생겼을까?" → 協 → きょう. 글자를 새로 외우는 게 아니라, **이미 입에 있는 소리에 글자를 붙인다.**
- **영어 ← 업무에서 쓰는 어휘.** 이미 읽고 쓰는 단어들이 출발점이다.
- **스페인어 ← 영어 어근.** `-tion → -ción`, `-ty → -dad`.

### 2. 설명하지 않는다. 먼저 추측하게 한다

카드 한 장은 이 순서로만 넘어간다. **추측 입력은 언제나 정답보다 먼저 온다.**

```
내 자료에서 그 글자 →  내가 아는 소리 →  부품 두 개 →  [내가 추측해서 입력]  →  정답 →  아는 단어로 착지
```

문법 설명 텍스트를 쓰지 않는다. 규칙을 먼저 보여주면 그건 다른 앱이 된다.

### 3. 소리는 눈으로 맞춘다

"여기서 억양을 올리세요"라고 쓰지 않는다. 대신 **내 목소리의 높낮이 곡선과 원어민 곡선을 겹쳐서 보여준다.** 같은 말을 다섯 번 하면 곡선 다섯 개가 쌓이고, 가까워지는 게 눈에 보인다.

## 수준을 묻지 않는다 — 대신 행동으로 안다

Anchor는 "초급/중급/고급"을 절대 묻지 않는다. 대신 **내 자료에서 뽑아낸 글자마다 "알아 / 몰라"를 누르게 한다.** 그게 유일한 수준 측정이다.

그 결과는 세 층으로 따로 기록된다. 사람의 앎은 한 덩어리가 아니기 때문이다.

| 층 | 뜻 | 예 |
| --- | --- | --- |
| 소리를 안다 | 발음은 안다 | "쿄오"는 들어봤다 |
| 뜻을 안다 | 의미는 안다 | "협력"의 뜻은 안다 |
| 말할 수 있다 | 입에서 나온다 | 실제로 소리 내어 말해봤다 |

**"협력은 아는데 協은 모른다"가 표현되어야 한다.** 이게 이 제품의 데이터 구조 전체가 서 있는 전제다.

다음에 볼 카드는 시험 점수가 정하지 않는다. **내가 아는 것에서 가장 가까운, 아직 모르는 것**이 자동으로 다음이 된다.

## Anchor를 쓰는 하루

> 아직 전부 되지는 않는다. 되는 것과 안 되는 것은 아래 "지금 어디까지 왔나"에 있다.

**아침 8:10, 지하철.** 일본어 메일 하나를 붙여넣는다. 3초 뒤 화면이 그 문장에서 한자 19개를 뽑아 두 묶음으로 나눈다 — 아는 소리가 있는 것, 아직 없는 것. 나는 아는 쪽 12개에 "알아"를 누르고, 모르는 7개 중 하나를 고른다.

**8:12.** 카드가 뜬다. `先日`에 밑줄이 그어져 있고 이렇게 말한다. **"'선'은 알잖아. 先만 모르는 거야."** 부품 두 개를 보여준다. 나는 뜻을 추측해서 입력한다 — "먼저". 정답이 열린다. `せん / before, ahead`. 내가 맞혔다.

**8:13.** 같은 카드가 소리로 넘어간다. 원어민 발음이 나오고, 나는 따라 말한다. 두 곡선이 겹쳐 보인다. 세 번 더 한다.

**8:15.** 그래프 한 장이 뜬다. `先`에 불이 들어왔고, 점선으로 두 글자가 가리켜진다. **"報를 아니까 収·談이 제일 가까워."** 오늘은 여기까지.

**오후 3:40, 회의 끝.** 하려다 못 한 말이 있었다. 한 줄 적는다 — "이건 다음 스프린트로 넘기는 게 나을 것 같아요." **앱이 답을 주기 전에 내가 먼저 영어로 써 본다.** 그다음에야 자연스러운 문장과, 그 안에서 소리로 연습할 덩어리가 나온다. 내 문장과 나란히 놓인다. 고쳐주지 않는다. 나란히 놓을 뿐이다.

**밤 11:00.** 하루 끝 화면. 오늘 만난 글자 넷, 말해본 것 하나. 내일 다시 만날 것 둘.

**2주 뒤 아침.** 새 기사를 넣었는데 `先`이 또 나왔다. **뽑기 화면이 아니라 기사 본문에서 그냥 읽힌다.** 그게 이 제품이 노리는 순간이다. 복습 카드가 아니라 **다음 자료에서의 재만남.**

## 무엇이 아닌가

이건 취향이 아니라 **금지 목록**이다. 이 중 하나라도 생기면 버그로 취급한다.

| 안 만드는 것 | 왜 |
| --- | --- |
| 레벨 테스트, "초급/중급/고급" 질문 | 아무도 정확히 답할 수 없다. 행동으로만 안다 |
| 커리큘럼, 오늘의 단어 | 순서는 내 자료와 내가 아는 것이 정한다 |
| 플래시카드 반복(SRS) | 복습은 카드가 아니라 다음 자료에서의 재만남이다 |
| 문법 설명 텍스트 | 설명하는 순간 발견이 사라진다 |
| 스트리크·포인트·리더보드 | 계속하는 이유가 점수면 이미 진 것이다 |
| 친구·공개 프로필 | 내 자료는 내 것이다 |
| 텍스트 채팅 회화, 문법 교정 | 목표는 소리다 |
| 한자 쓰기·필순 | 읽고 말하는 데 안 쓴다 |
| 준비 단계(씨앗 카드, 상황 고르기) | **첫 5분 안에 내 자료에서 내가 맞힌 글자가 하나 나와야 한다** |

## 내 데이터에 대한 약속

- **기본 비공개.** 공개는 항목 하나씩 내가 켤 때만.
- **추측 한 번, 녹음 한 번도 잃지 않는다.** 인터넷이 끊기면 브라우저에 담아뒀다 다시 올린다.
- **언제든 전부 내보낸다.** JSON 파일 하나로.
- **지우면 진짜 지운다.** 백업 사본까지.
- **녹음 원본은 30일 뒤 삭제.** 높낮이 데이터만 남는다.
- **내 자료를 외부 모델에 보낼 때는 학습에 쓰지 않는 설정으로 보낸다.** 보내는 것은 그 순간 필요한 한 줄뿐이다.

자세한 절차: [`docs/BACKUP.md`](./docs/BACKUP.md), [`docs/SECURITY.md`](./docs/SECURITY.md)

## 다 되면 이런 상태다 — 완성의 정의

한 문장으로: **2주 동안 매일 아침 내 자료를 넣고, 카드를 풀고, 소리 내어 말했고, 2주 뒤 새 자료에서 그때 만난 글자를 그냥 읽을 수 있다.**

그래서 판정은 감상이 아니라 **숫자 둘**로 한다.

| 숫자 | 무엇 | 통과 |
| --- | --- | --- |
| **재만남 인식률** | 2주 전 카드에서 만난 글자가 새 자료에 나왔을 때 그냥 읽히는 비율 | **70% 이상** |
| **곡선 일치도** | 같은 말을 다섯 번째 말했을 때 원어민 곡선과의 거리 | **1회차보다 가까워진다** |

두 숫자 다 **같은 것을 두 번 이상 만나야** 나온다. 그래서 만드는 시간만으로는 절대 나오지 않는다.

- 홈, 하루 끝, 설정, 다시 만날 것 표시

| 무엇 | 왜 막혀 있나 |
| --- | --- |
| **원어민 소리와 곡선** | 목소리 번호 두 개가 아직 안 들어갔다. **이게 없으면 통과 기준 둘 중 하나를 영영 못 잰다** |
| 지난 덩어리로 돌아가는 길 | 아직 안 만들었다. 같은 말을 다섯 번 하려면 이게 있어야 한다 |
| 저장 실패 시 다시 보내기 | 아직 안 만들었다. 위 약속 중 하나가 아직 약속일 뿐이다 |
| 스페인어 축 | 화면 그림만 있고 코드는 없다. **일부러 미뤘다** (아래 참고) |

가장 급한 종류다. 기능이 없는 것보다 나쁘다.

| 어디 | 무슨 거짓말 |
| --- | --- |
| 부품 화면 | 한자 **170자(8%)** 에서 부품이 빈 네모로 뜬다. 추측할 재료를 안 주고 추측하라고 한다 |
| 뽑기 화면 | 한자 **1,480자(69%)** 의 행이 "아는 소리가 없다"고 하는데, 우리 데이터에는 그 소리가 있다 |

| 첫 화면 | 브라우저 공유로 들어오라고 안내하는데 그 길이 없다 |

## 언제 무엇을 하는가

날짜의 기준은 **내가 실제로 쓰기 시작하는 날(D)** 이다. 아래 괄호 안 날짜는 **D = 9월 22일로 가정**한 것이고, 시작일이 정해지면 전부 따라 움직인다.

**중요 — 두 가지 시간이 섞여 있다.**

- **짓는 시간은 줄어든다.** 이 저장소는 하루에 286커밋이 났다. 원래 "3주"로 잡은 것이 하루에 끝나기도 한다.
- **쓰는 시간은 절대 안 줄어든다.** 2주는 무슨 수를 써도 2주다. 사람을 더 붙여도 안 된다.

그래서 **제일 늦는 길은 코드가 아니라 내가 앱을 여는 것**이다.

| # | 마일스톤 | 언제 | 끝났다고 말할 수 있는 조건 |
| --- | --- | --- | --- |
| **M0** | **거짓말 없애기** | D 전까지 (~9/22) | 화면이 말하는 것 중 실제로 안 되는 것이 **0개**. 위 "사실이 아닌 것" 표가 빈다 |
| **M1** | **첫 아침** | D (9/22) | 내가 내 진짜 자료로 카드 하나를 끝내고, 한 번 소리 내어 말한다. **원어민 소리가 나온다** |
| **M2** | **2주 쓰기** | D ~ D+13 (9/22~10/5) | 14일 중 **10일 이상** 열었고, 들어갈 길이 없어 주소를 직접 친 날이 **0일** |
| **M3** | **숫자가 나온다** | D+14 (10/6) | 재만남 인식률과 5회차 곡선을 **실제로 뽑아낸다**. 값이 좋은지는 여기서 안 따진다 |
| **M4** | **판정** | D+14 ~ D+16 (10/6~10/8) | 70%인가. 곡선이 가까워졌는가. **아니면 설계를 바꾼다** |
| M5~ | 그다음 | **정하지 않았다** | M4 결과를 보고 정한다 |

### M5 이후를 일부러 비워둔 이유

후보는 있다 — 자료가 저절로 들어오게 하는 입력 장치(브라우저 확장, 모바일 메모), 음성으로 주고받는 대화, 스페인어 축, 문법 블록.

**하지만 날짜를 잡지 않는다.** M4는 "가설이 틀렸다"로 끝날 수 있는 판정이고, 그때는 다음 단계가 아니라 설계가 바뀐다. 미리 잡은 일정표는 그 판정을 형식으로 만든다.

### 스페인어를 지금 안 만드는 이유

세 언어를 한 번에 만들면 **구멍이 세 벌 생긴다.** 지금 발견된 문제(빈 네모, 거짓 문구, 저장 실패)는 특정 언어의 문제가 아니라 축마다 똑같이 반복되는 문제다. 축을 하나 더 켜면 같은 구멍이 하나 더 늘 뿐이다.

그리고 **한국어 한자음 → 일본어 한자**가 이 제품에서 제일 강한 한 수다. 다른 앱이 못 하는 것이고, 여기가 되면 나머지는 같은 구조를 복사하면 된다. 여기가 안 되면 스페인어를 만들어도 소용없다.

"같은 구조가 세 언어에 다 통하는가"는 M4 뒤에 묻는다.

### 앵커 그래프 데이터 모델

- **노드**: 부품(한자 부수, 어근, 문법 구조, 대화 덩어리) 또는 단어. 언어 무관 공통 테이블.
- **엣지**: "부품 ∈ 단어", "한국 한자음 ↔ 음독", "영어 어근 = 스페인어 단어", "기능 분류(태도 9종)".
- **사용자별 노드 상태 3층**: `knows_sound`, `knows_meaning`, `can_say`. "협력은 아는데 協은 모른다"가 표현돼야 한다.
- **다음 카드** = 아는 노드에서 가장 가까운 모르는 노드. 추측 결과로 인접 노드 확신도 보정.

## 화면 흐름

언어는 라우트가 아니라 데이터 속성이다. 세 언어가 같은 화면을 재사용하고, 하단 탭바는 없다. 상단 왼쪽 "지금 어디" 라벨은 한 단계 위로 가는 링크라, 어느 화면에서도 홈까지 2탭이다.

기준은 하나다: **첫 5분 안에 "내 자료에서 내가 맞힌 한자" 하나가 생긴다.** 로그인 → 언어 고르기 → 자료 넣기(예시 자료 1개를 탭 한 번으로) → 뽑기 → 가나 6개 읽기(일본어 첫 카드 직전 한 번) → 카드 → 말하기 → 그래프 → 홈. 준비 단계는 없다.

라우트 표는 [docs/SITEMAP.md](./docs/SITEMAP.md), 화면 순서와 각 화면의 목적은 [docs/FLOW.md](./docs/FLOW.md).

### 디자인 시스템 요약

- 텍스트 세기 3단계로만 위계: `#2A2D33` / `#6B7078` / `#9AA0A8`. 순수 검정 금지.
- 강조는 글자색이 아니라 배경 틴트 `#E9EEF6`. 채도 높은 색, 그린·앰버 계열 금지.
- 배경 `#F6F6F7`, 카드 흰색 + 1px `#E6E7EA`, 반경 18px. 검은 주 버튼 1개(56px)만.
- 폰트는 Noto Sans KR / Noto Sans JP만. 세리프·모노스페이스 금지.
- 일본어 텍스트에는 항상 よみがな(ruby). 그래프·곡선에는 항상 범례.

## 배포

- 프로덕션: https://anchor-jessikang.vercel.app (Vercel 팀 `jessikang` → 프로젝트 `anchor`, 리전 icn1)
- DB·Auth: Neon 프로젝트 `anchor` (Vercel 마켓플레이스 통합, 싱가포르). Neon 조직이 Vercel 관리형이라 프로젝트는 Vercel Storage 에서 만든다.
- 통합이 `DATABASE_URL`(소유자)·`NEON_AUTH_BASE_URL` 을 주입하고, 앱은 별도로 넣은 `ANCHOR_DATABASE_URL`(anchor_app) 만 쓴다.
- `main` 에 푸시하면 자동 배포된다. 마이그레이션은 자동으로 돌지 않는다: 새 SQL 파일을 만들면 `pnpm db:migrate` 를 손으로(또는 Neon MCP 로) 적용한 뒤 푸시한다.
- Google 로그인은 Neon Auth 의 공용 개발 자격증명으로 동작한다. 공개 전에 Google 클라이언트를 직접 등록한다 (docs: https://neon.com/docs/auth/guides/setup-oauth).

## 개발

```bash
pnpm install
cp .env.example .env.local        # 값 채우기 (아래 표)
pnpm db:migrate                    # DATABASE_URL_ADMIN(또는 DATABASE_URL) 로 스키마 + RLS 적용
pnpm kanji:build                   # KANJIDIC2 + IDS → db/seed/kanji.json (상용한자 2,136자, 이미 커밋돼 있어 보통은 생략)
pnpm db:seed                       # 공용 참조 노드 적재 (한자 2,136 + 부품 + 한국 한자음, 영어 어근·덩어리 40)
pnpm dev                           # http://localhost:3000
```

| 변수 | 무엇 |
| --- | --- |
| `ANCHOR_DATABASE_URL` | 앱 런타임 연결. 마이그레이션이 만드는 `anchor_app` 역할 (RLS 우회 불가) |
| `DATABASE_URL_ADMIN` | 마이그레이션·백업 전용. 테이블 소유자. 없으면 Vercel Neon 통합이 주입한 `DATABASE_URL` 을 쓴다 |
| `ANCHOR_APP_PASSWORD` | 0001 마이그레이션이 `anchor_app` 을 만들 때 쓰는 비밀번호 |
| `NEON_AUTH_BASE_URL` | Neon 콘솔 → Auth → Configuration 의 Auth URL. Google 제공자를 켜 둔다 |
| `NEON_AUTH_COOKIE_SECRET` | `openssl rand -base64 32` |
| `NEON_API_KEY` / `NEON_PROJECT_ID` / `NEON_BRANCH_ID` | 배포 전 스냅샷 (프로덕션만) |
| `CRON_SECRET` · `BLOB_READ_WRITE_TOKEN` | 매일 JSON 백업 (`/api/cron/backup` → Vercel Blob). Blob 토큰은 Vercel 이 주입 |

```bash
pnpm typecheck && pnpm lint && pnpm build   # 커밋 전
pnpm db:migrate:status                       # 마이그레이션 상태
pnpm design:tokens                           # design/tokens.json → src/app/tokens.css
pnpm design:check O01 http://localhost:3000/?fixed=1   # 한 화면만 참고 HTML 과 픽셀 비교 (.design-check/)
pnpm design:diff                             # 매핑된 화면을 전부 훑어 차이가 큰 순서로 세운다 (판정 아님)
# 둘 다 서버를 ANCHOR_DESIGN_PREVIEW=1 로 띄워야 로그인 없이 찍힌다 (예시 데이터, 로컬 전용)
# 결과를 읽는 법(정상인 차이 셋)은 design/SCREENS.md "참고와 구현의 차이 훑기".
curl localhost:3000/api/health               # DB 역할·RLS 상태 (rls_all_enabled 가 true, role_bypasses_rls 가 false 여야 한다)
```

### 데이터 접근 규칙

- 사용자 데이터 쿼리는 전부 `withUser(userId, tx => …)` 안에서. 트랜잭션마다 `app.user_id` 를 SET LOCAL 하고 RLS 정책이 그 사용자 행만 허용한다. 자세한 건 [db/README.md](./db/README.md).
- 내보내기 `GET /api/export`, 계정 삭제 `POST /api/account/delete`. 백업·복구 절차는 [docs/BACKUP.md](./docs/BACKUP.md).

## 작업 방식

- 기능 하나 = 화면 하나. `design/screens/`의 해당 HTML을 열어 레이아웃·문구를 그대로 옮긴다. 문구를 임의로 늘리지 않는다.
- 새 화면을 만들면 [`CLAUDE.md`](./CLAUDE.md) 의 원칙 0–4와 위 "무엇이 아닌가"에 걸리는지 스스로 점검하고, 걸리면 만들지 않는다.
- 세션마다 소유 영역이 다르다. 남의 영역은 고치지 말고 그 세션에 요청한다 ([docs/TEAM.md](./docs/TEAM.md)).
