# 검증 플로우 (QA 기준 문서)

무엇을 어떤 순서로 눌러 보고, 각 지점에서 무엇이 참이어야 하는지를 이 문서가 정한다. 소유는 `Anchor · QA`(`docs/TEAM.md` 1장).

판정 기준은 `docs/FLOW.md` 다. 코드가 FLOW 와 다르면 코드가 틀린 것이고, FLOW 자체가 어색하면 기획 문제다. **QA 는 사실을 대고 등급을 매긴다.** 코드 문제인지 기준 문서 문제인지, 완결로 볼 수 있는지는 PM 과 기획이 판단한다(`docs/TEAM.md` 3장).

## 1. 범위

| 한다 | 하지 않는다 |
| --- | --- |
| 화면을 실제로 눌러 보고 결함을 찾는다 | 코드를 고친다 |
| 항목마다 통과·실패와 등급을 적는다 | 완결을 선언한다 |
| 실패를 FLOW 의 어느 절과 어긋나는지로 댄다 | 무엇을 고칠지 설계한다 |
| 코드 결함은 개발에, 기준 문서 문제는 PM 에 보낸다 | 같은 건을 두 곳에 보낸다 |

## 2. 준비

### 계정

한 라운드는 **초기화된 계정**으로 돈다. 이전 라운드의 언어·자료·카드 상태가 남아 있으면 첫 방문 경로가 그대로 재현되지 않는다.

초기화는 `POST /api/account/delete`(body `{"confirm":"삭제"}`)로 한다. 로그인한 상태에서만 되고, 복구되지 않는다. 프로덕션 계정에 쓰지 않는다.

### 띄우는 법 — 실계정 (판정에 쓰는 것)

로컬 Postgres 와 시험 로그인으로 돈다. 개발이 자기 컨테이너에서 확인한 순서 그대로다.

```bash
# 1. Postgres. 루트로는 initdb 가 안 되고, 경로는 /var/lib/postgresql/ 아래여야 한다 (스크래치패드는 postgres 계정이 못 지나간다)
mkdir -p /var/lib/postgresql/anchor && chown postgres:postgres /var/lib/postgresql/anchor
su postgres -c "/usr/lib/postgresql/16/bin/initdb -D /var/lib/postgresql/anchor/data -A trust -U postgres"
su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/postgresql/anchor/data \
  -o \"-k /var/lib/postgresql/anchor -p 5433 -c listen_addresses=127.0.0.1\" \
  -l /var/lib/postgresql/anchor/log start -w"
# 2. DB 이름은 반드시 neondb (0001 이 GRANT CONNECT ON DATABASE neondb 를 박아 둬서 다른 이름이면 멈춘다)
createdb -h 127.0.0.1 -p 5433 -U postgres neondb
# 3. 환경 변수 파일 (값은 전부 로컬 더미. ANCHOR_APP_PASSWORD 와 ANCHOR_DATABASE_URL 의 비밀번호는 같아야 하고, 쿠키 비밀값은 32자 이상)
#    DATABASE_URL_ADMIN=postgresql://postgres@127.0.0.1:5433/neondb
#    ANCHOR_APP_PASSWORD=<더미>   ANCHOR_DATABASE_URL=postgresql://anchor_app:<더미>@127.0.0.1:5433/neondb
#    NEON_AUTH_BASE_URL=https://local.invalid/neondb/auth   NEON_AUTH_COOKIE_SECRET=<32자 이상>
#    ANCHOR_TEST_LOGIN=1   ANCHOR_TEST_USER_ID=qa-local-1
. /var/lib/postgresql/anchor/env.sh
# 4. 스키마와 씨앗. db:seed 를 건너뛰면 F03 에서 한자가 하나도 안 뽑힌다 — 그건 결함이 아니다
pnpm db:migrate && pnpm db:seed
# 5. 앱
pnpm dev
```

시험 로그인: `GET /api/test-login` 이 `anchor_test_session` 쿠키(12시간)를 심고 `/today` 로 보낸다. 새 계정이면 `/today` 가 `/onboarding/languages` 로 보내는 것이 정상이다. 계정 행은 `/today` 가 만든다. 나가기는 `/api/test-login?logout=1`. 이 라우트는 `route.dev.ts` 라서 `ANCHOR_TEST_LOGIN=1` 인 로컬 dev 에만 존재한다.

라운드마다 초기화는 `POST /api/account/delete` (`{"confirm":"삭제"}`). **로컬에서는 502 가 정상이다** — Neon Auth 주소가 자리표시자라 마지막 단계만 실패하고 DB 는 이미 비워진 뒤다. 프로덕션에서는 200 이다.

라운드를 돌기 전에 `git merge origin/main` 뒤 `pnpm install` 을 한다. 의존성이 낡으면 typecheck·build 가 깨지는데 이건 코드 결함이 아니라 내 환경 문제다. 화면이 지워졌는데 `.next/dev/types` 가 남아 있어도 같은 증상이 난다.

### 띄우는 법 — 미리보기 (모양만)

`ANCHOR_DESIGN_PREVIEW=1` 은 로그인·DB 없이 예시 데이터로 화면을 그린다. 모양·문구·접근성은 이 모드로 봐도 된다. **상태가 바뀌는 항목은 이 모드로 판정하지 않는다.** `src/lib/env.ts` 가 모듈 평가 시점에 환경 변수를 요구하므로 형식만 맞는 더미 값이 있어야 한다.

### 뷰포트

390×844. 모바일 우선이 전제이므로 이 크기에서 나온 것만 결함으로 센다.

### 결함이 아닌 것

- `/talk` 은 영어를 켜지 않으면 307 → `/today`. F13·F14 는 설정에서 영어를 켠 뒤 본다.
- `/graph` 는 `?card=` 없이 열면 307 → `/today`. F11 은 카드에서 들어가는 화면이다.
- `ANTHROPIC_API_KEY` 가 없으면 카드 문안은 사전 조합(`content_source: fallback`)으로, F14 영어 문장은 쓴 한국어 줄 그대로 나온다. `ELEVENLABS_API_KEY` 가 없으면 `/api/tts` 는 204 이고 F10·F14 는 "브라우저 음성이야" 한 줄을 보인다. 키 없는 환경의 정상 동작이다.
- 헤드리스 브라우저에는 마이크가 없다. O03 "읽기 시작"은 곧바로 마이크 착지(O03b)로 가고, F10·F14 "말하기"는 "마이크를 허용하지 않았어"로 끝난다. 인식 0개 갈래와 녹음 저장은 마이크 있는 브라우저에서만 판정한다.

## 4. 화면 공통

경로 위의 모든 화면에서 매번 본다. `docs/FLOW.md` 4장과 `CLAUDE.md` 디자인 시스템이 근거다.

| 무엇 | 참이어야 하는 것 |
| --- | --- |
| 뒤로 | 상단 왼쪽 "지금 어디" 라벨을 누르면 한 단계 위로 간다. 어느 화면에서도 홈까지 2탭 이내 |
| 이탈 | 한 화면에 이탈 링크 1개. 의미가 반대인 두 이탈을 같은 화면에 두지 않는다. 확인 화면의 실행 링크("지울게")는 이탈이 아니라 그 화면이 하는 일이라 따로 센다 |
| 주 버튼 | 검은 주 버튼 1개. 고를 것이 둘이면(알아/몰라, 언어) 둘 다 검은 버튼이 아니라 선택 칩이다. **되돌릴 수 없는 일은 검은 주 버튼에 없다.** 주 버튼은 돌아가는 쪽이고, 실행은 그 아래 회색 링크이며 확인 입력 전에는 꺼져 있다 |
| 어휘 | 내부 용어(씨앗·노드·앵커·그래프에 심는 중)가 화면에 없다. 상태 어휘는 아는 것 / 오늘 / 다음 세 개 |
| 알약 | 알약은 시스템 상태이고 켜짐 / 꺼짐 / 이어서 세 개뿐. 알아/몰라는 선택 칩이다. 언어 켜기(O02a·설정)는 켜고 끄는 것이라 켜짐/꺼짐 알약이다(1장 2·1′장) |
| 단계 표시 | "일본어 2 / 3" 같은 온보딩 단계 표시가 없다. 세는 것은 카드 안의 "카드 1 / 4"와 진행 막대 6칸 둘뿐이고 섞이지 않는다 |
| 시간 | 홈 자료 행에 소요 시간이 없다. 시간은 F15 마지막 줄에만 쓴다 |
| 글자색 | T1 #2A2D33 · T2 #6B7078 · T3 #9AA0A8 밖의 글자색이 없다. 순수 검정이 없다 |
| 강조 | 강조가 글자색이 아니라 배경 틴트다. 채도 높은 색, 그린·앰버가 없다 |
| 글자 크기 | 13px 미만이 없다. 본문이 15px 이상이다. 한자 표시가 44~132px 안이다 |
| 폰트 | Noto Sans KR / Noto Sans JP 뿐이다. 세리프·모노스페이스가 없다 |
| 제목 | 화면마다 `h1` 이 하나다. 그 아래는 건너뛰지 않고 차례로 내려간다(h1 → h2 → h3). 상단 "지금 어디" 라벨은 제목 태그가 아니다 |
| 대체 텍스트 | 뜻을 나르는 그림·아이콘에 대체 텍스트가 있다. 장식은 빈 값이라 읽히지 않는다. 한자는 그림이 아니라 텍스트다 |
| 탭 영역 | 누르는 것의 세로·가로가 44px 이상이다. 보이는 크기가 아니라 영역 기준이다. `pnpm design:lint` 가 참고 HTML 쪽을 검사한다 |
| 그래프 | 그래프·곡선에 범례가 있다 |
| 마이크 | 사용자가 버튼을 누른 뒤에만 켜진다 |
| ruby | 일본어 한자에 よみがな가 있다. 가나·가타카나에는 없다. 읽기를 본문으로 크게 보여 주는 자리에 중복해서 달지 않는다 |

글자색·강조·글자 크기·폰트·제목·대체 텍스트·탭 영역·그래프·ruby 는 `CLAUDE.md` 디자인 시스템, 나머지와 ruby 를 가리는 시점은 `docs/FLOW.md` 4장이 근거다. 주 버튼 줄은 둘 다에 있다. 기준 문서 밖의 줄은 없다.
