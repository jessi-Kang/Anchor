# 검증 플로우 (QA 기준 문서)

무엇을 어떤 순서로 눌러 보고, 각 지점에서 무엇이 참이어야 하는지를 이 문서가 정한다. 소유는 `Anchor · QA`(`docs/TEAM.md` 1장).

판정 기준은 `docs/FLOW.md` 다. 코드가 FLOW 와 다르면 코드가 틀린 것이고, FLOW 자체가 어색하면 기획 문제다. **QA 는 사실을 대고 등급을 매긴다.** 코드 문제인지 기준 문서 문제인지, 완결로 볼 수 있는지는 PM 과 기획이 판단한다(`docs/TEAM.md` 3장).

## 1. 범위

| 한다 | 하지 않는다 |
| --- | --- |
| 화면을 실제로 눌러 보고 결함을 찾는다 | 코드를 고친다 |
| 항목마다 통과·실패와 등급을 적는다 | 완결을 선언한다 |
| 실패를 FLOW 의 어느 절과 어긋나는지로 댄다 | 무엇을 고칠지 설계한다 |
| 코드 결함은 개발에, 기준 문서 문제는 PM 에 보낸다 | 같은 건을 두 곳에 보낸다 |

## 2. 준비

### 계정

한 라운드는 **초기화된 계정**으로 돈다. 이전 라운드의 언어·자료·카드 상태가 남아 있으면 첫 방문 경로가 그대로 재현되지 않는다.

초기화는 `POST /api/account/delete`(body `{"confirm":"삭제"}`)로 한다. 로그인한 상태에서만 되고, 복구되지 않는다. 프로덕션 계정에 쓰지 않는다.

### 띄우는 법

라운드를 돌기 전에 `git merge origin/main` 뒤 `pnpm install` 을 한다. 의존성이 낡으면 개발이 새로 쓴 패키지를 못 찾아 typecheck·build 가 깨지는데, 이건 코드 결함이 아니라 내 환경 문제다. **결함으로 올리기 전에 이것부터 확인한다.** 화면이 지워졌는데 `.next/dev/types` 가 남아 있어도 같은 증상이 난다. 그 폴더를 지우고 다시 본다.

`src/lib/env.ts` 가 모듈 평가 시점에 환경 변수를 요구한다. 값이 없으면 모든 라우트가 500 이다.

```bash
ANCHOR_DESIGN_PREVIEW=1 \
NEON_AUTH_BASE_URL=... NEON_AUTH_COOKIE_SECRET=... ANCHOR_DATABASE_URL=... \
pnpm dev
```

`ANCHOR_DESIGN_PREVIEW=1` 은 로그인·DB 없이 예시 데이터로 화면을 그린다. 모양·문구·접근성은 이 모드로 본다. **상태가 바뀌는 항목(무엇이 저장되는지, 큐에서 빠지는지, 다음 화면이 어디인지)은 이 모드로 판정하지 않는다.** 실제 계정으로 돈 결과만 판정에 쓴다.

`next dev` 는 `CLAUDE.md` 끝에 `nextjs-agent-rules` 블록을 덧붙인다. 커밋 전에 `git checkout -- CLAUDE.md` 로 지운다.

실제 계정 라운드는 Google 로그인을 거쳐야 하는데, QA 세션 컨테이너에는 자격 증명이 없어 헤드리스로 로그인할 수 없다. 둘 중 하나가 있어야 3장을 끝까지 돌린다.

- Jessi 가 이 문서를 따라 직접 한 번 돈다.

그때까지 QA 가 돌릴 수 있는 것은 4장(화면 공통)과 `ANCHOR_DESIGN_PREVIEW=1` 로 보이는 화면의 모양·문구뿐이다.

## 4. 화면 공통

경로 위의 모든 화면에서 매번 본다. `docs/FLOW.md` 4장과 `CLAUDE.md` 디자인 시스템이 근거다.

| 무엇 | 참이어야 하는 것 |
| --- | --- |
| 뒤로 | 상단 왼쪽 "지금 어디" 라벨을 누르면 한 단계 위로 간다. 어느 화면에서도 홈까지 2탭 이내 |
| 이탈 | 한 화면에 이탈 링크 1개. 의미가 반대인 두 이탈을 같은 화면에 두지 않는다 |
| 주 버튼 | 검은 주 버튼 1개 |
| 어휘 | 내부 용어(씨앗·노드·앵커·그래프에 심는 중)가 화면에 없다. 상태 어휘는 아는 것 / 오늘 / 다음 세 개 |
| 알약 | 알약은 시스템 상태이고 켜짐 / 꺼짐 / 이어서 세 개뿐. 사용자가 고르는 것은 선택 칩이다 |
| 단계 표시 | "일본어 2 / 3" 같은 온보딩 단계 표시가 없다. 세는 것은 카드 안의 "카드 1 / 4"와 진행 막대 6칸 둘뿐이고 섞이지 않는다 |
| 시간 | 홈 자료 행에 소요 시간이 없다. 시간은 F15 마지막 줄에만 쓴다 |
| 글자색 | T1 #2A2D33 · T2 #6B7078 · T3 #9AA0A8 밖의 글자색이 없다. 순수 검정이 없다 |
| 강조 | 강조가 글자색이 아니라 배경 틴트다. 채도 높은 색, 그린·앰버가 없다 |
| 글자 크기 | 13px 미만이 없다. 본문이 15px 이상이다. 한자 표시가 44~132px 안이다 |
| 폰트 | Noto Sans KR / Noto Sans JP 뿐이다. 세리프·모노스페이스가 없다 |
| 제목 | 화면 제목이 `h` 태그다 |
| 대체 텍스트 | 의미 있는 이미지에 대체 텍스트가 있다 |
| 탭 영역 | 누르는 것의 세로·가로가 44px 이상이다 |
| 그래프 | 그래프·곡선에 범례가 있다 |
| 마이크 | 사용자가 버튼을 누른 뒤에만 켜진다 |
| ruby | 일본어 한자에 よみがな가 있다. 가나·가타카나에는 없다. 읽기를 본문으로 크게 보여 주는 자리에 중복해서 달지 않는다 |

탭 영역과 ruby 는 `CLAUDE.md` 디자인 시스템, ruby 를 가리는 시점은 `docs/FLOW.md` 4장이 근거다.

제목 태그와 대체 텍스트 두 줄은 기준 문서에 아직 없다. PM 에 올려 둔 상태이고, 기준에 들어가면 이 표에서 근거만 바꾼다.

## 6. 등급

하나만 고른다. 같은 뿌리에서 여러 화면이 깨지면 뿌리 하나로 센다.

| 등급 | 무엇 | 예 |
| --- | --- | --- |
| **막힘** | 경로가 끊긴다. 다음으로 갈 수 없거나, 돌아갈 수 없거나, 틀린 데이터가 저장된다 | 주 버튼이 404 로 간다. 뒤로 갈 길이 없다. 안 배운 한자가 큐에서 빠진다 |
| **헷갈림** | 갈 수는 있는데 뜻이 잘못 전달되거나 사용자가 잘못 고르게 한다 | 안 한 일이 통과로 기록된다. 두 답 중 하나가 정답처럼 보인다. 화면이 폐기된 개념을 말한다 |
| **다듬기** | 뜻은 통하는데 기준과 다르다 | 어휘가 규칙 밖이다. 문구가 사실과 다르다. 탭 영역이 44px 아래다 |

**막힘 0건**이 첫 방문 경로의 합격선이다(`docs/TEAM.md` 3장).

등급은 사용자에게 무슨 일이 일어나는지로 정한다. 고치기 쉬운지 어려운지로 정하지 않는다.

## 8. 도구

| 무엇 | 어떻게 |
| --- | --- |
| 참고 HTML 대조 | `pnpm design:check <화면 ID> <URL>`. `.design-check/` 에 참고·앱·차이 이미지가 남는다. 글리프 차이로 1~3%는 정상이고, 그 위는 레이아웃 차이를 의심한다 |
| 화면 보기 | Playwright 로 390×844 전체 화면을 찍는다 |
| 4장 자동 검사 | 같은 세션에서 글자 크기·글자색·탭 영역·제목 태그·대체 텍스트를 DOM 에서 센다 |

자동 검사는 4장의 일부만 덮는다. 경로가 끊기는지, 문구가 사실인지, 무엇이 저장되는지는 사람이 눌러 봐야 안다.
